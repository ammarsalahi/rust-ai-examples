# Text Classification

## Overview

This example builds a **multi-class text classifier** on top of a BERT encoder. Rather than
downloading a pretrained model from the Hub, it loads a **local** BERT checkpoint from disk
(`models/config.json`, `models/model.safetensors`, `models/vocab.txt`).

The workflow is a *feature-extraction + linear-probe* transfer-learning pipeline:

1. Build a WordPiece tokenizer in code from `vocab.txt`.
2. Run every sentence through the frozen BERT encoder and take the `[CLS]` vector as a
   fixed-size sentence embedding.
3. Train a single `Linear` layer (`hidden_size -> num_classes`) on those embeddings with
   AdamW and cross-entropy loss.
4. Save the trained head to `models/classifier_h{hidden}_c{classes}.safetensors`.
5. Enter an interactive loop that classifies new text.

Because the BERT weights never change, training is fast and only a tiny number of parameters
are learned. This is the classic "linear probe" way to reuse a pretrained encoder.

## Data and Model Files

### `data/dataset.csv`

A header row followed by one example per line. The labels are arbitrary strings; the program
discovers the unique set automatically.

```csv
text,label
Rust is a systems programming language,programming
Python is used for software development,programming
The developer created a REST API,programming
```

### `models/config.json`

The local BERT is a small model. The program prints these values at startup and reads
`hidden_size` from them:

```json
{
  "hidden_size": 128,
  "intermediate_size": 512,
  "max_position_embeddings": 512,
  "num_attention_heads": 2,
  "num_hidden_layers": 2,
  "model_type": "bert",
  "vocab_size": 30522
}
```

### `models/vocab.txt`

A plain text file with one token per line (the standard BERT `[PAD]`, `[UNK]`, `[CLS]`,
`[SEP]`, ... vocabulary). It must contain `30522` entries to match `vocab_size`.

### 13. `stratified_split` (Lines 515-549)

```rust

    let mut groups: Vec<Vec<LabeledSample>> = (0..=max_label).map(|_| Vec::new()).collect();

        groups[sample.label].push(sample.clone());

```

- Buckets samples by class so each class can be split independently.

```rust
    let mut rng = rand::rng();

    for group in &mut groups {
        group.shuffle(&mut rng);

        let mut train_size = ((group.len() as f32) * train_ratio).round() as usize;

        if group.len() > 1 {
            train_size = train_size.max(1).min(group.len() - 1);
        } else {
            train_size = group.len();
        }

        train.extend_from_slice(&group[..train_size]);
        validation.extend_from_slice(&group[train_size..]);
    }

    train.shuffle(&mut rng);
    validation.shuffle(&mut rng);
```

- Shuffles each class group, then assigns `train_ratio` of it to training.
- The `max(1).min(len - 1)` guard guarantees at least one sample in each side as long as a
  class has two or more members; a singleton class goes entirely to training.
- Finally both partitions are shuffled so classes are interleaved during training.

:::caution
`stratified_split` uses `rand::rng()`, a **non-seeded** thread RNG, so the split differs on each
run. If you need reproducible training, replace it with a seeded `StdRng` (as the other
examples in this repository do).
:::

- Per epoch: reset metrics and shuffle the sample order.

```rust
        for &index in &indices {
            let (embedding, label) = &train[index];

            let input = Tensor::new(embedding.as_slice(), &device)?.reshape((1, classifier.hidden_size))?;
            let target = Tensor::new(&[*label as u32], &device)?;

            let logits = classifier.linear.forward(&input)?;
            let loss = cross_entropy(&logits, &target)?;

            let loss_value = loss.to_scalar::<f32>()?;
            total_loss += loss_value as f64;

            let prediction = argmax_row(&logits)?;
            if prediction == *label {
                correct += 1;
            }

            optimizer.backward_step(&loss)?;
        }
```

- **Online (per-sample) SGD-style updates.** Each iteration reshapes one embedding to
  `[1, hidden]`, computes logits `[1, classes]`, the cross-entropy loss, and immediately calls
  `backward_step`, which runs backprop *and* the optimiser step.
- Accuracy is counted from `argmax` of the logits.

```rust

        let validation_accuracy = evaluate_classifier(classifier, validation)?;
        let average_loss = if train.is_empty() { 0.0 } else { total_loss / train.len() as f64 };

        println!(
            "epoch {:>2}/{:<2} | loss {:.4} | train {:.2}% | validation {:.2}%",
            epoch, EPOCHS, average_loss, train_accuracy * 100.0, validation_accuracy * 100.0,
        );
```

- Prints an average loss and both accuracies each epoch, so the effect of training is visible.

## Running the Example

The model files must already exist in `models/` (this example does **not** download them).

```bash
cd examples/text-classification
cargo run
```

The first run trains and saves the classifier. Subsequent runs detect
`models/classifier_h{hidden}_c{classes}.safetensors` and load it instead of training.

To force a fresh training run:

```bash
rm models/classifier_h*_c*.safetensors
cargo run
```

## Key Concepts

1. **Feature extraction + linear probe** — freeze the encoder, cache embeddings once, train a
   tiny head. Far cheaper than fine-tuning the whole transformer.
2. **WordPiece built from `vocab.txt`** — shows the individual tokenizer components
   (normalizer, pre-tokenizer, post-processor, truncation, padding) rather than hiding them
   behind a `tokenizer.json`.
3. **Deterministic label ordering** — `BTreeSet` guarantees the same class ids across runs.
4. **Separate parameter store** — `VarMap` makes the head independently saveable/loadable
   while the BERT weights stay in a read-only memory map.
5. **Shape discipline** — fixed `MAX_LENGTH` padding plus explicit length assertions keep the
   tensor shapes predictable.

## Notes and Limitations

- The encoder is frozen: `model.safetensors` is never updated, so quality is bounded by the
  pretrained BERT and the expressiveness of a single linear layer.
- Training uses one sample per optimiser step (batch size 1) and a non-seeded RNG, so results
  are not perfectly reproducible. Use a seeded `StdRng` and/or mini-batches for stability.
- There is no early stopping or learning-rate schedule; `EPOCHS` and `LEARNING_RATE` are the
  only knobs.
- All inputs are padded to 64 tokens even when much shorter, which is simple but wasteful.
